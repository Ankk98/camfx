# camfx v0.2.0a1 (Fedora alpha)

This is the first Fedora-focused alpha RPM release distributed via GitHub Releases.

## What's included
- `camfx` single RPM package
- CLI daemon and core effects pipeline
- systemd user unit: `camfx.service`
- GNOME app launcher entry: `camfx.desktop`

## Install (Fedora)
Download the RPM asset from this release, then run:

```bash
cd ~/Downloads
sudo dnf install -y ./camfx-0.2.0a1-*.x86_64.rpm
```

## Required: V4L2 loopback setup (manual for this alpha)
`v4l2loopback` is not auto-configured by this release yet. Run this first:

```bash
sudo dnf install -y v4l2loopback akmod-v4l2loopback v4l-utils
sudo modprobe v4l2loopback exclusive_caps=1 card_label="camfx" video_nr=-1
v4l2-ctl --list-devices
```

If needed after reboot, run the same `modprobe` command again before starting `camfx`.

## Enable and run daemon
```bash
systemctl --user daemon-reload
systemctl --user enable --now camfx
systemctl --user status camfx --no-pager
```

## Basic runtime checks
```bash
camfx --help
journalctl --user -u camfx -n 100 --no-pager
```

## GUI (alpha)
- The GUI is included in this `camfx` package for `v0.2.0a1`.
- GNOME app menu shortcut is installed automatically (`camfx`).
- Start it from a terminal with:

```bash
camfx gui
```

- For full control from GUI, keep daemon running with D-Bus support (default in packaged service).
- GTK runtime dependencies are included in RPM requirements.

## Stop daemon
```bash
systemctl --user stop camfx
systemctl --user status camfx --no-pager
```

## Notes
- This is an alpha release (`0.2.0a1`), intended for testing and feedback.
- Virtual camera support depends on local V4L2 loopback setup (`v4l2loopback`).
- Packaging automation and split packages are intentionally deferred to later releases.
